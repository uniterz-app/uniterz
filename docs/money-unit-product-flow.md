## 1. 全体構造

Uniterz では、以下の 3 つを明確に分離する。

| 区分 | 内容 |
|---|---|
| **お金** | Pro 機能を利用するためにユーザーが支払う |
| **Unit** | 予想成績、ランキング、招待等により運営が無料付与する |
| **商品** | ユーザーが Unit を使用して交換申請し、運営が購入・配送する |

### 基本構造

```
ユーザーのお金 → ストア決済 → 運営
運営 → 条件達成ユーザーへ Unit を無料付与
ユーザー → Unit を使用して商品交換申請
運営 → 正規販売店から商品を購入 → ユーザーへ配送
```

**お金から Unit へ直接変換する経路は作らない。**

---

## 2. ユーザーから運営へ入るお金

ユーザーが運営へ支払うお金は、原則として **Pro 利用料金のみ**とする。

| プラン | 料金 | 更新 |
|---|---|---|
| Weekly | 280 円 | 7 日ごとの自動更新 |
| Monthly | 780 円 | 1 か月ごとの自動更新 |
| Season Pass | 5,000 円 | シーズンごとの買い切り |

### 対価に含むもの

- PRO INSIGHT
- 試合直前アラート
- 週次レポート
- 月次レポート（Monthly・Season Pass のみ）
- Pro Skin / Pro バッジ / My Rank 専用表示 / その他 Pro 限定ビジュアル

### 対価に含めないもの

- Unit
- ランキング上の加点
- Unit の獲得倍率
- 商品交換権の優遇
- 予想回数の増加
- グループバトルでの優遇

---

## 3. Pro 課金時のお金の流れ

### App Store・Google Play で購入する場合

1. ユーザーがプランを選択する  
2. Apple または Google が決済を処理する  
3. ストアが購入情報を発行する  
4. Uniterz のサーバーが購入情報を検証する  
5. 検証完了後、Pro 利用権を有効化する  
6. ストア所定の手数料等を控除した金額が運営へ支払われる  

運営は、端末上の購入完了表示だけで Pro を有効化せず、ストアの購入情報をサーバー側で確認する。

### 決済失敗時

- Pro 利用権を即時停止するか、ストアの猶予期間を適用する
- 再請求が成功した場合は Pro を継続する
- 再請求が失敗したまま利用期間が終了した場合は Pro を停止する
- Unit、通常ランキング、商品交換資格には影響させない

---

## 4. 解約・返金時のお金の流れ

### 解約

Weekly・Monthly を解約した場合、自動更新だけを停止する。

- 支払い済み期間中は Pro を利用できる
- 利用期間終了後に Pro 機能を停止する
- 通常 Pro Skin と Achievement Skin は装着できなくなる
- 解放履歴やレポートデータは保存する
- 再加入後に再利用できるようにする

### 返金・決済取消し

返金またはチャージバックが成立した場合は、該当する Pro 利用権を終了または修正できる。

Pro 加入によって Unit を付与しないため、原則として以下は取り消さない。

- ランキング / グループバトル / 招待 / 特別イベントで獲得した Unit

ただし、決済不正と Unit 不正が関連している場合は、別途不正利用として調査する。

---

## 5. Unit が発生する流れ

Unit は、運営からユーザーへ無料で付与するアプリ内報酬とする。

### 主な付与経路

- 個人週間 / 月間ランキング
- グループバトルの週間 / 月間ランキング
- 招待制度 / 招待マイルストーン
- 特別イベント / 期間限定キャンペーン
- 運営が事前告知したその他の施策

### 付与の基本フロー

1. ユーザーが予想・招待等の条件を達成する  
2. システムが総合スコアや達成条件を集計する  
3. 運営が試合結果、不正、複数アカウント等を確認する  
4. 結果を確定する  
5. 対象ユーザーへ Unit を付与する  
6. 付与理由、付与量、有効期限を履歴へ記録する  

---

## 6. Unit とお金の分離

Unit には、以下の機能を持たせない。

- 有料購入 / 現金への換金 / 払戻し
- 他ユーザーへの譲渡・販売・送金
- 外部ポイントへの交換
- Pro 料金への充当
- 予想への賭け入れ / 予想失敗による減少

Unit は、運営が指定する商品の交換申請にのみ使用できる。

### 設けない経路

- 現金 → Unit  
- Unit → 現金  
- Unit → 他人の Unit  

---

## 7. Unit の管理状態

| 状態 | 内容 |
|---|---|
| 付与予定 | 条件達成後、確認中 |
| 保有中 | 商品交換に利用できる |
| 交換申請中 | 商品交換のため一時的に利用停止 |
| 消費済み | 運営が商品を購入した後 |
| 期限切れ | 有効期限を経過 |
| 取消済み | 不正・誤付与等により取消し |

### 履歴に残す項目

ユーザー ID / 増減 Unit 数 / 増減理由 / 対象ランキング・イベント / 処理日時 / 有効期限 / 交換申請 ID / 不正取消しの理由 / 運営またはシステムの処理識別子

**残高だけを上書きせず、取引履歴を保存する。**

---

## 8. 商品交換申請の流れ

ユーザーが必要 Unit を保有している場合、指定商品との交換を申請できる。

| 商品 | 必要 Unit | 商品価格上限 |
|---|---|---|
| NBA ジャージ | 1,000 Unit | 25,000 円 |
| NBA Tシャツ | 600 Unit | 10,000 円 |
| NBA キャップ | 300 Unit | 6,000 円 |

NBA ジャージはスウィングマンを基本とし、価格上限内であればオーセンティックも対象とする。

### 交換フロー

1. ユーザーが希望商品の情報を入力する  
2. 必要 Unit を「交換申請中」にする  
3. 運営が商品、価格、販売店、在庫、配送地域を確認する  
4. 条件を満たしていれば運営が正規販売店から購入する  
5. 購入完了時に Unit を「消費済み」にする  
6. 販売店または運営からユーザーへ発送する  
7. 注文情報と配送情報を記録する  

---

## 9. 商品購入時のお金の流れ

商品の代金は運営が正規販売店へ支払う。

```
運営の事業資金 → 正規販売店 → 商品 → ユーザー
```

ユーザーが商品代金を運営へ支払う仕組みにはしない。

| 負担 | 内容 |
|---|---|
| 運営（原則） | 商品代金、通常の国内送料、通常の海外送料 |
| 海外ユーザー | 関税、輸入税、現地配送会社の手数料、受取国の公租公課 |

ユーザー負担が発生する可能性は、申請前に明示する。

---

## 10. 商品価格が上限未満の場合

商品価格が設定上限を下回っても、使用 Unit 数は減らさない。

例: 6,000 円の Tシャツでも 600 Unit / 20,000 円のジャージでも 1,000 Unit / 4,000 円のキャップでも 300 Unit

### 行わないこと

- 差額分の Unit 返還
- 差額分の現金返還
- 差額分を次の交換へ繰越し
- ユーザーからの追加料金による価格上限超過商品の購入

商品交換条件を固定し、Unit と円を細かく連動させない。

---

## 11. 在庫切れ・価格変更時の逆処理

運営が商品を購入する前に、在庫切れ・サイズ欠品・価格上限超過・対象外販売店・配送不可・正規品確認不可・商品ページ削除が発生した場合は商品を購入しない。

1. ユーザーへ変更を依頼する  
2. 別商品が選択された場合は審査を継続する  
3. 申請を取り消す場合は、交換申請中の Unit を保有中へ戻す  
4. シーズン交換上限には算入しない  

---

## 12. 購入後のキャンセル・返品

運営が商品を購入した後は、原則として Unit を返還しない。

ユーザー都合（サイズ・イメージ・不要・変更希望・住所ミス）は交換対象外。

販売店規定で対応する場合: 注文内容と異なる / サイズ・カラー違い / 到着時の重大破損 / 初期不良 / 運営・販売店の明らかなミス。

販売店から返金を受けた場合の Unit 処理:

| 原因 | 基本方針 |
|---|---|
| 運営・販売店側で商品提供不能 | Unit 返還を基本 |
| ユーザー側 | Unit 返還なしを基本 |
| 一部返金 | 規約に定めた方法で処理 |

---

## 13. 不正時の流れ

1. Unit の付与を保留する  
2. 関連する予想・ランキング・招待履歴を調査する  
3. 不正に関係する Unit を取り消す  
4. 未処理の商品交換申請を停止または取消しする  
5. 必要に応じてランキングから除外する  
6. 重大または反復した場合はアカウントを停止する  

商品購入後に不正が判明した場合は、商品の返還または商品代金相当額の請求を行う場合がある。

---

## 14. Free・Pro の分離

Free と Pro では、以下の条件を同一とする。

- 予想可能回数 / 総合スコアの計算 / ランキング参加条件
- Unit 付与対象・付与量 / グループバトル条件 / 招待制度条件
- 商品交換条件 / 商品価格上限 / シーズン交換上限

Pro ユーザーが料金を支払っていることを理由に、Unit や商品の面で有利にしない。

---

## 15. 運営の収入と支出

### 主な収入

- Weekly / Monthly / Season Pass 料金
- 将来導入する場合のスポンサー・広告等

### 主な支出

- ストア決済手数料
- NBA データ API 費用
- サーバー・AI・システム費用
- 商品購入費 / 国内外の送料
- 返金・配送事故への対応費
- 法務・会計費用 / マーケティング費用

Unit を付与した時点では現金を支払わず、**商品交換が成立した時点で商品代と送料が実際の支出になる**。

### 継続管理する指標

発行済み Unit 総数 / ユーザー保有 Unit 総数 / 期限切れ予定 Unit / 商品交換申請数 / 商品別交換率 / 想定商品原価 / 実際の商品購入費 / 配送費 / シーズン交換上限 / 将来発生する可能性のある交換費用

---

## 16. 会計上の確認事項

税理士・会計士へ確認する項目:

- ストア決済の売上計上額 / ストア手数料の処理
- 無料体験後の売上計上時期
- 返金・チャージバックの処理
- 商品購入費の勘定科目 / 配送料・関税の処理
- ユーザーへ提供する商品の税務上の扱い
- 発行済み未使用 Unit について引当て等が必要か
- 海外ユーザーからの売上に関する消費税・税務処理

---

## 17. 実装上の重要条件

- お金と Unit の台帳を完全に分ける
- Pro 購入処理と Unit 付与処理を接続しない
- Unit を有料商品としてストアへ登録しない
- 商品購入前は Unit を保留状態にする
- 商品購入後にのみ Unit を消費済みにする
- Unit の付与・取消し・期限切れを履歴保存する
- 同じランキングや招待で重複付与できないようにする
- 不正確認前に商品購入を行わない
- 商品交換申請にシーズン上限を適用する
- Free・Pro で Unit 付与条件を分岐させない

---

## 18. 全体フロー

### Pro 課金

```
ユーザー
  ↓ Pro料金
Apple / Google
  ↓ 手数料等を控除
運営
  ↓
Pro利用権を提供
```

### Unit 付与

```
ユーザー
  ↓ 予想・ランキング・招待等
運営が結果と不正を確認
  ↓
Unitを無料付与
```

### 商品交換

```
ユーザー
  ↓ Unitを使用して交換申請
運営
  ↓ 商品・在庫・価格を確認
正規販売店
  ↓ 運営が商品代を支払う
ユーザーへ商品配送
```
